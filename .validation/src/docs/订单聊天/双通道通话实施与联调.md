# 双通道通话实施与联调

本页说明已实现的代码接线和现场放行条件。源码开发与自动化测试均通过远端仓库进行，正式代码只在 workers/chat，临时回归只在 workers-server/main。

## 已实现的链路

会话页提供语音／视频通话和通话记录入口。协作群从当前可沟通成员中选择一人进行1v1，不创建多人会议。账号前台核对来电，接听、拒接、取消、挂断通过同一Go用例处理。来电只在小程序前台提示，不冒充离线系统电话推送；微信原生媒体窗口使用官方1v1能力。

Go持久保存邀请、双方账号占用、设备实例、不可变操作键、revision和attempt epoch。HTTP与WSS共用严格字段解码和原订单权威／成员代次／禁聊守卫。账号可持续拨打和长通话，没有个人分钟、次数或固定单通时长。双方每人一个活动call属于忙线互斥。记录分页独立于正文已读，不写聊天read_seq。

PHP独占共享免费资源账本：每家一个真实scope／周期池，语音视频共享，两个通道单位不相加。原子预占覆盖双方、短效媒体凭证和停流安全余量；续约将R移入待对账L。服务端时间按每端累计上界估算，不把客户端计时或SDK状态当官方用量。官方完整报表按单调累计量及覆盖水位导入，只有已完整覆盖分录才能退休L。

相邻且同scope、AppID、计量规则的真实新周期已核验时，事务提前预占新周期段，同一call／epoch可以继续；旧段留旧账。没有有效新G、统计陈旧或周期缺口则安全停止。未知媒体跨越未登记周期时继续冻结，不能凭日历恢复额度。

只有已明确拒绝且从未签发媒体凭证的建立失败，才允许一次备选通道。先持久冻结旧attempt、取得PHP未提交释放墓碑，再同时切换双方epoch。网络超时、丢响应、媒体提交后不自动换供应商；旧epoch不能取新票据。Go锁外调用PHP，持久中间态支持原操作恢复。

声网使用固定官方agora-miniapp-sdk@2.6.5及官方AccessToken2；通道名绑定环境／应用／call／epoch，每端固定UID只在自己的通道有效。小程序全量转发SDK要求的状态事件，语音以audio-only入房，支持静音、听筒和切摄像头。没有录制。隐藏、退出、换号、失权和授权过期会清理本机媒体；迟到凭证或SDK响应不能复活已结束通话。

后台沿用权限、CSRF、版本CAS和当前角色复核。可设置路由、登记真实权益、调整B/S/X、导入官方完整快照、暂停／复核池，查看分通道G/B/O/L/R/S/X、30天估算分录、最近通话、审计与20%／10%／不可分配提醒。提醒仅站内记录，每池每阈值一次；无短信、钱包、充值或自动购买。

## 配置与访问

- PHP `chat.calls_enabled=false`、Go `calls.enabled=false`、数据库 `chat_call_settings.config_json.enabled=false` 为默认值。登记池不会开启总开关。
- Go需要既有身份、MySQL、Redis、会话与消息组合。生产还须通过check-chat-release.py的独立`calls`能力封印，不能借audio/video媒体消息能力放行通话。
- PHP内部资源入口 `POST /chat-calls.php` 仅在私有TLS/FPM虚拟主机开放，使用现有HMAC、环境、nonce与正文摘要，公网返回404。Go `calls.php_endpoint` 固定该HTTPS路径。
- 公共 `POST /chat/api/v1/calls/{availability,create,inbox,status,history,prepare,accept,reject,end,pulse,ready,prepared}` 使用原用户凭证；不接受客户端provider、OpenID、UID、quota、release或media_stopped。
- PHP `chat.internal_go_origin` 指向私有TLS的Go内部监听，`POST /chat/internal/v1/calls/stop-confirmed` 只接受已有HMAC管理员停止证明。9502不能暴露公网。
- 两端复用同一环境的 `CHAT_INTERNAL_KEY`（32字节标准Base64）和key_id。供应商私钥仅通过服务器环境变量引用：`CHAT_SHENGWANG_CERTIFICATE`、`CHAT_SHENGWANG_CUSTOMER_ID`、`CHAT_SHENGWANG_CUSTOMER_SECRET`；AppID须匹配登记池。不得写入小程序或日志。
- Go账号只新增五张自有表的明确SELECT/INSERT/UPDATE/DELETE授权：chat_call_accounts、chat_call_sessions、chat_call_legs、chat_call_operations、chat_call_events。不能授予数据库通配写权限或PHP资源表写权限。
- PHP负责其余八张通话表：settings、resource_pools、resource_calls、resource_operations、resource_ledger、usage_snapshots、admin_audit、alerts。安装与未发布2.7.0整包相同，manifest仅更新新装和2.7.0校验值；VERSION及已发布历史保持。
- 通话维护随既有worker启动，每5秒核对；优先活动租约，最多8个并发维护任务，未知关断轮转。实际容量须在目标主机验收。运行设置的窗口不是产品时长上限。
- 紧急停用应先关闭后台功能总开关并保留内部资源RPC和worker，以便结束／结算在途通话；全部确认后再停进程或关闭物理入口。

## 供应商停止与真实放行

声网关断先请求官方channel级禁入规则，再查询官方channel不存在；两者确认后才进入终态并向PHP结算释放。请求失败、频道仍存在或PHP结算ACK丢失时保留占用和R，原操作继续核对。必须在实际项目验证该REST能力、权限和边界，自动化仅模拟媒体响应。

微信官方1v1尚无已核实可用的服务端按call关闭／查询接口，因此代码不会用双方客户端exit、断网、Token到期或本地倒计时证明媒体已停。该通道保持待核验；真实供应商免费硬边界与退房证据确认后，管理员可凭证明摘要记录停止，Go核验当前call／epoch后结算。若不能可靠约束未知活动媒体，继续关闭微信通道。不能把这条人工核验路径描述成自动服务端强踢。

现场EXT06仍需：iOS／Android两真机双通道、麦克风／摄像头拒绝与恢复、原生窗口前后台、弱网／断线／旧Token、长通话持续续约、免费到额硬停、真实权益和完整用量范围、跨周期、崩溃／恢复及实际主机容量。测试夹具不产生真实通话，也不能替代这些证据。不开启收费兜底。

恢复检查点已纳入13张新表的摘要。恢复旧备份后先保持门禁关闭，补齐独立增量，核对官方周期用量、预占和未知媒体，不能只恢复聊天页面就放行，也不重拨历史邀请。升级前应按既有维护流程结束并确认活动通话；有未知媒体时保持维护并人工核对。
