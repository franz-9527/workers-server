# 音视频通话双通道与平台共享免费额度

[主设计](订单聊天系统设计与开发说明.md)通话资源附录，2026-10-26按用户最新要求定版。本文是目标设计；EXT03.a已实现独立状态/共享算术/路由契约，实际通话、后台额度页面、持久资源预占和自动停用仍未实现；代码进度只看[清单19节](开发拆分与验收清单.md#19-当前进度与下一轮交接唯一进度入口)。

## 1. 当前规则与范围

1. 微信官方双人音视频与声网RTC小程序是两个独立媒体通道，合用其真实可用的免费资源。资源属于平台/供应商计费范围，不属于个人。
2. 所有合法用户共用资源，不设个人、角色、账号的日/月分钟数、次数额度、付费等级、冷却权益或固定单通时长；双方均不收费。单人可以持续使用，直到全局资源或真实业务权限不再允许。
3. 取消旧稿个人语音/视频免费拨出额度、发起方扣个人额、成本乘2、视频超额收费、充值续通和通话钱包预占。本文保留旧文件路径以兼容链接；旧方案仅留在Git历史，不作为当前实现分支。
4. 微信与声网各自有一个共享的音视频总池；同一池内语音、视频按供应商规则竞争资源，不能再给两种媒体各复制一份总量。两个供应商单位不同，不直接相加为“总分钟”。
5. 一个通道耗尽，后续呼叫使用另一个符合条件的通道；两个池都耗尽时停止语音和视频通话，不转付费、不买包、不自动续订、不扣任何用户钱包。免费资源不足以覆盖某种视频、但还可覆盖语音时，仅视频不可用，仍可重新发起语音。
6. 本期先做1对1。S24群里可选择一名当前合法成员通话，不把微信群接口或声网多人能力直接扩展为全群视频。普通后台抽检者不能借此加入或呼叫成员；真正业务介入仍遵循S24授权。
7. 首期不录音录像、不做通话ASR、不上传通话媒体到七牛。既有语音/视频消息、存储期限及原短信/钱包业务保持原规则；拒绝通话权限仍可用文字和已开放的消息能力。

双方各一个活动通话占用用于防止同一接听端同时接通多通、跨设备抢接和互拨竞态，它是通话状态互斥，不是个人消费限额；不得另设“每人每天N通/最长N分钟”作为放行条件。协议级幂等、防重放、平台总并发/供应商配额与既有当前身份/禁聊规则仍需执行。

## 3. 用户功能与媒体边界

- 会话工具栏提供“语音通话”“视频通话”，沿用固定昵称/头像及真实身份。S24仅从有合法业务关系的当前成员中选一人；不是任意联系人拨号。
- 发起、响铃、被叫确认接听、准备媒体、接通、挂断/拒接/取消/忙线/超时状态完整；每次动作有固定call_id和幂等键。邀请30秒过期可作为初值，不是通话时长上限。
- 通道由服务端选定，两端同通道、同一次attempt。不能一端微信原生、一端声网，也不要求用户理解供应商才能拨打。
- 微信通道使用已授权的setEnable1v1Chat/join1v1Chat与原生接听/结束能力，双方均在小程序；声网使用小程序SDK及自有接听UI。均不承诺小程序关闭后的系统来电、离线自动拉起。
- 视频首期480p、上限720p，按SDK可用档位控制，默认不启美颜/虚拟背景/超分等增值项；弱网提示可结束后改语音。实时通话编码按所选SDK/微信兼容能力验证，不套用历史视频文件“H265必用”要求。
- 每通媒体类型固定；首期不在通话中自动切换类型。用户改语音/视频需明确结束后重发，防止原生切换导致资源系数失真。若未来支持切换，须先实现类型分段与新额度原子预占。
- 通话记录仅显示类型、参与者、时间和状态（如未接听、已取消、已结束、资源用尽），没有个人剩余额度、充值、单价或录音播放。用户侧不展示平台精确用量/其他用户数据。

当前订单/售后episode、双方授权、冻结/禁聊及S24成员区间仍在创建、接听、媒体入房、凭证更新和活动续约时复验。关单/改派/撤权结束正常客户端，不能用另一供应商绕开业务拒绝或恢复被移除成员。群内自选“商家/团队师傅”不获得订单或呼叫管理权。

## 4. 路由、降级与无额度停用

默认auto_free路由：语音优先微信→声网，视频优先声网→微信；优先级可在后台按媒体类型独立调整。理由是先保留微信原生语音体验，同时避免微信历史视频高倍率先耗光其语音可用池；这是产品策略，不改变任何供应商真实计量。管理员可显式关闭某通道。

| 状态 | 行为 |
| --- | --- |
| 首选通道可用且预占成功 | 固定本attempt通道，并发占用成功后向双方签发准备凭证 |
| 首选耗尽/已确认不可用，备选可用 | 在实际媒体建立前预占备选，继续本次邀请；不重弹两次来电 |
| 两池真实耗尽 | 拒绝新呼叫，显示“本月平台免费通话额度已用完，额度恢复后可继续使用”；没有充值入口 |
| 仅剩安全余量或低于最小可执行窗口 | 显示“当前安全可用额度不足，额度恢复后可继续使用”；如实保留官方余量，不能宣称供应商余额已为0 |
| 仅视频预占不足但可语音 | 显示“当前视频通话额度不足，可改用语音通话”，由用户主动改选，不自动改变媒体类型 |
| 尚有额度但被预占/并发暂满 | 显示“当前通话繁忙，请稍后重试”；不能把预占当永久已用完 |
| 未核验/用量过旧/对账异常/供应商故障 | 该通道不可准入，尝试已核验备选；均不可用显示“通话服务暂不可用，请稍后重试”，不虚报额度耗尽 |
| 通话中本通道无法续资源 | 提前提示并在已获授权的安全边界结束；备选可用时给“使用其他通道继续”按钮，用户确认后重建媒体，不自动重拨 |
| 下周期恢复 | 各池仅在其真实新周期权益确认后恢复；有一个已确认可用即可恢复相应呼叫，不补发未接通历史呼叫 |

只有明确未提交媒体、已确认未入房/已离房、旧attempt已失效才可自动尝试另一个通道。create/join超时、回执未知、单边已入房时保留预占并查询/围栏原操作，不盲目跨供应商重试。普通业务拒绝、取消、被叫拒接或邀请过期不能触发“换一家继续打”。

每次跨通道恢复使用新attempt_epoch及双方确认；旧epoch的SDK事件、票据、Token、迟到接听都不能恢复旧媒体。一个attempt最多一次可靠的建立前降级，两个通道之间不循环尝试。

## 6. 共享账本、计量与防重复扣减

PHP CallQuota是资源池、权益证据、用量快照、预占/结算/纠正台账唯一写入方；Go只写呼叫信令/媒体状态并调用受保护PHP用例。不创建个人额度账本、不涉及现金钱包，不沿用旧CallBilling价格/voip_video收费类型。

按provider+真实quota_scope+cycle唯一建池，计量用整数及有理数。建议内部以1/100原始等效秒为最小单位，系数保存分子/分母；类型字段严格区分wechat_equivalent与shengwang_standard，禁止浮点扣减或把两池直接求和。后台显示可换算为分钟，保留内部精度。

若声网本账号确认为小程序1.43/4.29，分别使用143/100、429/100并对每个真实入房参与端累计；不是只记发起方时长。计费开始/结束按当前供应商加入/订阅/离开规则，而非只从前端“接通”计到挂断；只有一人入房、等待媒体或断线未离房也可能产生消耗，必须纳入保守预占。

微信若复核仍为按每接收端整分钟进位，则基于每端整通累计时长计算差额，不能每15秒心跳重新进位一次。未接听是否消耗不能仅按用户界面决定：能够证明未实际入媒体才释放全部；已入房部分/未知入房仍占用平台资源，不向用户收费。

定义G=经核验且未到期的官方免费权益，B=平台使用上限（默认G且不得大于G），O=官方已确认消耗，L=尚无证明已被官方快照覆盖的平台用量上界，R=尚未转换成L的未来活动预占，S=安全余量，X=其他共享系统/上报延迟的不确定余量。可准入量A=max(0,min(G,B)-O-L-R-S-X)。

O、L、R互斥迁移：本次已发生段从R移入L；只有带完整范围/统计水位且证明覆盖某些本地段的官方快照到达，才能把该段从L移出。没有可靠覆盖水位的官方总数，宁可暂时保守重复扣除，不凭max(官方用量,本地用量)猜测重合后释放；未知差异需核验才能恢复可用，不能重复增加免费资源。

后台提高“本地可用量”、清除告警或导入旧报表不产生新G；错误/回退官方快照保留旧版本、挂异常；有审计的纠正只追加分录，不删除旧账本。未返回的供应商统计与其他应用的共用消耗不能忽略，未能界定X或供应商免费边界时不满足零超额启用条件。

## 7. 并发预占、租约与耗尽处理

采用全平台共享短窗口，不为每个用户预留月配额。初值可为60秒资源窗口、提前15秒续约、15秒活动心跳；仅内部结算粒度，资源充足则持续续约，不是每通60秒上限。

PHP按稳定provider/scope/cycle顺序锁池→call资源记录→reservation/window；reserve与可用量检查同事务。仅在同一通道为两个参与端一起预占成功后返回prepare授权。两人共用一次call预占，不在被叫accept再重复预占双端；新增实际媒体leg按受控attempt记账。Go跨设备互斥先短占用，PHP失败后查原操作并补偿；Go不持聊天/授权事务锁等待PHP。

同一个operation_id/call/attempt/window同参数返回原结果、变参拒绝。响应丢失查询原操作，不重复预占；MySQL提交前不ACK可用，Redis仅聚合心跳和唤醒。R→L、结算/释放与对应分录一次事务完成，重放不多扣；Redis TTL或进程重启不能证明媒体已退出。

续约同时核验双方当前权限、共享剩余、当前周期和供应商可执行的停用边界。预占必须覆盖签发凭证可继续使用的最长有效期、关断延迟及计费进位，不能只预留60秒却签发可持续一小时的发流权限。采用短效凭证并在续签复验，但Token到期不一定强制已入房用户退房，须用本SDK已验证的服务端踢人/禁发/供应商免费资源边界兜底。

最后一笔可用资源已被其他活动通话预占时，阻止新通话但继续兑现既有R；预占不是立刻消耗。两池可分配量都不足时暂停新呼叫；活动通话只使用其已预占段，无法续约时提示并在安全边界结束。两个总池耗尽后不得让活动媒体无限运行，也不能提前没收已预占资源制造任意固定时长。

跨月按供应商真实周期分别切段，旧月实际用量留旧账，未来段在新周期的G确认后才预占；不能仅因为北京时间到了1日就凭空恢复两家资源。旧月迟到回调写旧池，新月恢复不重放旧邀请。有效新周期权益已确认且可安全约束的活动call可继续，不要求无故重拨。

## 8. 官方用量接入、硬停边界与失败关闭

### 8.1 查询和核验来源

实施前逐一核验微信/声网是否有本账号可用的官方用量/权益API、统计延迟、回调签名、账单范围及数据留存。公开文档当前不足以证明两通道均有每秒实时、每通签名用量及服务端强踢能力；不得编造接口或用客户端秒数冒充官方实时结算。

有官方API则后端定时拉取/签名回调去重，页面读取已持久快照；无API则受权运营导入报表或带证明的用量快照，记录采集人、覆盖范围/截止水位、来源hash及核验时间。浏览器抓取控制台/保存账号密码不能作为正式同步方案；手工录入不是供应商赠送，原始证明置私有存储并限制访问。

平台同时记录有来源的双端事件、服务端时序、入房/离房和续约，提供估算与保守预占，不伪称官方数值。同步超过最大陈旧时间/覆盖不完整时不能新扩额度；已有经预占且有可靠强停边界的段按原授权执行，到边界停止，不凭旧余额无限续。

### 8.2 “只用免费、耗尽即停”的放行条件

优先核验供应商是否能设置仅用免费资源、禁后付费/自动购买，并在免费额度到边界由供应商强制停止；不得把“账号没充值”或本地布尔开关当供应商不扣费保证。已有付费包、统一账户余额、其他项目共享消耗和增值服务都要排除或计入风险边界；本轮不修改/停用已有外部服务。

若某通道没有可确认的供应商免费硬边界，则必须同时具备足够保守的全范围用量上界、原子预占和已经真机验证的服务端停发/退房手段，覆盖丢心跳、改包客户端、旧Token重放、失联和进程崩溃；仅让正常客户端exit不满足硬停要求。

特别是微信官方1v1，旧设计已经记录未核实服务端按call强踢/签名用量。本次不将业务租约虚称为媒体强停。若既不能确认免费资源由微信强制到额停服，也不能可靠约束活动媒体，则微信通道保持“待核验/暂停”，可先使用满足条件的声网；相反情况同理。两个都不满足条件则功能待开放，不通过付费降级满足可用率。

运营可设置安全余量以覆盖计量/报告/关断延迟，但它不是任意收费授权，也不能用一个猜测百分比证明绝对零超额。后台明确显示“官方用量”和“估算待对账”；“零付费、最终停用”验收通过前不向真实用户启用该通道。

### 8.3 故障与恢复

- PHP/MySQL不可用：不新预占/不新续约；Go不靠Redis缓存发新媒体凭证。已授权段靠供应商围栏按安全边界结束，恢复后查询原记录。
- Redis不可用：暂停新呼叫占用；持久R/L保留，不当作免费资源恢复。可从持久状态重建，不触发自动重拨。
- 供应商请求/退房未知：冻结原attempt及必要预占，停止向该通道分配新资源，查询或人工核验；未确认媒体停止不得定时释放全部预算。
- 恢复旧备份：重建两家周期池、官方快照水位、R/L及未知attempt，确认无陈旧Token/活动媒体后才开放。不能只恢复聊天卡片而丢掉已用量。
- 手动紧急停用：停止准入与凭证续签、通过已验证能力结束活动媒体，并记录运营原因；不开启另一通道绕过全局停用。

拟PHP内部资源接口为calls.resources.reserve/renew/commit_usage/release/status，使用既有Go↔PHP受保护HMAC/nonce/环境/幂等协议；窗口提交必须来自可信服务端，普通客户端不能直接填剩余量/系数或释放R。每次复验当前源版本，响应丢失查status，不新建操作重试。

后台calls.settings/quota/usage/reconcile/import/stop复用原后台控制器/权限/CSRF；客户端calls.availability只返回可用类型、可操作状态和本次选择，不返回其他人用量、平台剩余精确数字或密钥。没有个人quota/quote/recharge/bills入口。

终态outbox回写最小通话卡片不计普通新正文，重复事件不新增多条；业务read_seq、接听和资源结算互不替代，后台访问不写用户已读。
