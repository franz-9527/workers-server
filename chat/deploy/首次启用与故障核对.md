# 测试站聊天首次启用与故障核对

适用现有目录 /www/wwwroot/workers-test、PHP 运行目录 /server、Go 端口 19501/19502。**Git 编译成功、宝塔进程为绿色、后台“开放”开关开启，都不等于小程序已能收发聊天。** 2026-10-31 起默认使用“PHP 已安装配置 + 后台聊天设置”自动生成 Go 私有运行配置，不再要求重复维护数据库、签名公钥和核心会话开关；chat/chat.json 仅作为高级兼容配置来源。

历史诊断（2026-10-31）：测试站 PHP 健康接口为 2.7.1，GET /chat/api/v1/auth/session 曾返回 CHAT_ROUTE_NOT_FOUND（404）。这不是当前部署状态的结论；请以后台最新诊断、实际 `chat/bin/state/chat.runtime.json` 和当前启动日志为准。小程序 chat.credentials 503 只能说明 PHP 依赖未就绪，不能据此猜测缺少哪项凭据。

## 1. 先核对正在使用的进程与配置

宝塔 Go 项目 bixuan_chat_test 应使用：

- 执行命令：/bin/bash /www/wwwroot/workers-test/chat/deploy/bt-run.sh
- 公开监听：127.0.0.1:19501；内部监听：127.0.0.1:19502。
- 默认有效配置：/www/wwwroot/workers-test/chat/bin/state/chat.runtime.json（启动前自动生成）。
- 默认私有运行环境：/www/wwwroot/workers-test/chat/bin/state/runtime.env（启动前自动生成，0600）。
- chat/chat.json：高级兼容配置来源；仅设置 CHAT_CONFIG_MANUAL=1 时才直接作为完整运行配置。
- chat/deploy.local.env：仅保留 Go/PHP 路径、运行用户等机器级覆盖，不再要求重复填写 PHP 数据库密码。
- 网站仍以 /server 为运行目录，19502 不代理到公网。不要另启动第二套 serve/worker。

检查 Go 项目日志中的 serve_started、监听端口、退出原因，以及 chat/bin/state/running-sha 是否对应当前发布。只读查看实际环境与各 enabled 项，不把整个含私有信息的配置粘贴到聊天或日志。配置中 auth.enabled=false、auth.public_keys={} 是“基础进程已启动，身份功能未配置”，不是完成部署。

## 2. 身份签名：后台生成，PHP 持有种子，Go 只持有公钥

优先使用“后台 → 聊天管理 → 聊天设置 → PHP ↔ Go 签名”。不再要求先去宝塔手工生成 Base64 seed、修改 PHP-FPM 池环境变量和人工派生公钥。

首次启用：

1. 以超级管理员进入聊天设置，点击“生成 PHP 签名密钥”。PHP 使用 sodium 生成 32 字节 Ed25519 随机 seed，通过项目现有私密值加密机制写入非公开 `system_settings`；后台、接口和日志都不返回 seed。
2. 页面自动派生 Key ID、公钥指纹和公钥环；默认运行模式由 `server/bin/chat-runtime-config.php` 在 Go 启动前自动把公钥同步到 `chat/bin/state/chat.runtime.json`，无需复制或编辑 `chat.json`。
3. Go 同时自动继承当前 PHP 站点的环境、MySQL host/port/database/username/password；测试站继续使用测试站现有数据库，正式站继续使用正式站现有数据库，不新增聊天数据库。
4. 在“Go 服务配置”中只维护 Go 独有项，例如 Redis 地址/密码。保存后重启现有宝塔 Go 项目，再按第 4 节检查身份路由与真实测试账号。
5. 测试站和正式站分别在各自数据库与 `app.key` 下生成签名状态，不跨环境复用；PHP `testing` 对应 Go `test`。

后台网页请求不会直接控制或重启 Go。配置值写入现有数据库；真正的 Go 私有运行文件由服务器端 CLI 启动链路生成，生成后再启动/重启 Go。常规操作缩减为“后台生成签名/设置 Redis → 重启 Go”，不再复制数据库或公钥配置。

### 2.1 密钥轮换

后台密钥模式下可点“轮换签名密钥”。系统生成新的 Key ID 和 seed，PHP 会立即开始用新 Key ID 签发；公钥环最多保留最近 3 个公钥，覆盖尚未过期的旧 JWT。轮换后重启 Go 项目即可自动刷新公钥环，不再手工修改 `chat.json`。单个 PHP 聊天访问凭证最长 5 分钟。

### 2.2 环境变量兼容模式

原有 `chat.seed_env` 仍保留为高级覆盖／兼容方案，默认 `CHAT_ACCESS_SEED`。如果 PHP-FPM 中该变量存在且是标准 Base64 的 32 字节 seed，**环境变量优先**，后台只显示其派生公钥和 Go 配置，并禁止覆盖或轮换，避免同一站点出现两个私钥来源。

已有环境变量部署无需迁移即可继续使用。需要改为后台模式时，先移除对应 PHP-FPM 环境变量并重载 FPM，再进入聊天设置生成；不要把旧 seed 粘贴进后台、聊天或日志。

## 3. 启用身份不等于启用收发

完整收发还需要按现有主部署文档核对以下配置，不能只把所有 enabled 一次改成 true：

| 能力 | 实际前提 |
| --- | --- |
| auth | 后台签名可用；默认自动继承当前 PHP 数据库与站点环境 |
| conversations | auth、MySQL、订单授权与会话投影 |
| history | auth/conversations、同环境独立的游标签名密钥 |
| safety | test 文字使用真实身份及本地反私单风控；AV 另需真实微信短期凭证和审核回调；正式站仍须官方安全能力及独立发布验收 |
| messages | auth/conversations/history/safety/MySQL 同时满足 |
| socket | auth/MySQL/Redis；WSS 代理与票据能力可用 |
| operations / release | 对应环境恢复核验及已有发布条件满足 |

默认模式下 MySQL 直接复用当前 PHP 站点已经隔离好的数据库和账号，不再创建第二套数据库，也不要求重复填写密码；运行时密码仅写入 `chat/bin/state/runtime.env`。Redis 密码如有则由后台加密保存，启动时短暂导出到同一私有运行环境文件。短信、图片、音视频、安全审核等仍按各自配置与验收开启；不要为了消除报错盲目打开全部收费或媒体能力。

详细字段和门禁以 [主部署文档第 12 节及后续能力章节](../../docs/订单聊天/宝塔部署、容量与运维.md#12-s03认证配置与宝塔接入前核对未部署) 为准。需要先验证界面和客户／师傅角色时，可使用后台测试中心模拟会话，它独立于真实 Go 服务及真实密钥。

## 4. 修改后验证

使用现有启动器及其同一份受保护环境运行配置检查，--probe 仅检查已配置 MySQL/Redis等依赖，不自动建表或开启功能。校验成功后在宝塔重启现有 Go 项目，不直接再执行 bt-run.sh 创建重复进程。

服务器本机可只读查看：

~~~bash
curl -fsS http://127.0.0.1:19501/livez
curl -sS http://127.0.0.1:19502/readyz
~~~

- /livez 的 alive 只表示进程响应。
- /readyz 仅本机可读；基础依赖通过不等于消息业务已启用，不开放内部端口。
- 对外 GET /chat/api/v1/auth/session 应进入已开放身份处理器；404 CHAT_ROUTE_NOT_FOUND 说明路由未开放或配置未生效。若返回方法／身份错误，仍需继续检查合法登录的 POST，不把该错误视为全部完成。
- 小程序正常登录后，chat.availability 应返回 enabled=true，chat.credentials 应返回 200；不要把访问凭证复制到地址栏、命令行或聊天。
- 最后用授权的测试账号验证实际会话查看与收发，不能用宝塔绿色状态、build 标记、PHP 就绪或模拟会话结果代替真实 Go 验证。

## 5. 错误定位

| 现象 | 优先核对 |
| --- | --- |
| PHP 503 CHAT_SIGNING_NOT_CONFIGURED | FPM sodium、FPM 池环境变量、PHP key_id/seed_env；仅配置 Go 环境不够 |
| PHP 未就绪 CHAT_RECOVERY_NOT_READY | 原安全恢复核验，不通过就保持关闭 |
| Go 404 CHAT_ROUTE_NOT_FOUND | 正在使用的私有配置、auth/history/messages/socket 各自开关及实际二进制版本 |
| Go 身份验证失败 | kid、公钥对应关系、PHP testing ↔ Go test、系统时间与当前登录会话 |
| 502 或连接失败 | Go 进程、19501 监听、Nginx 上游；与 PHP 凭证 503 分开定位 |

本次只读核对未修改服务器、生成真实密钥或重启进程。密钥示例用于管理员在服务器现场完成配置；不要把密钥文件粘贴给支持人员。

## 7. 502 防重试与自动模式隔离（2026-10-31）

自动模式不再把 `chat/chat.json` 当底稿，避免历史手工配置继续污染自动生成结果；只有显式设置 `CHAT_CONFIG_MANUAL=1` 才读取该文件。启动器会把最近一次安全状态码写入 `chat/bin/state/last-error`，后台“聊天设置”直接显示 deployed/running/current 三个版本和 19501/9501 本机监听状态。PHP `chat.availability` 现在同时要求 Go 本机端口已监听；Go 未启动时小程序保持禁用，不再持续请求 `socket-ticket` / `conversations/digests` 制造 502 重试噪声。


### 7.1 后台诊断不得影响业务

Go 状态探针是辅助诊断，不是 PHP 后台的强依赖。若 PHP 禁用了 `stream_socket_client` / `readlink`，或 open_basedir 阻止读取聊天状态目录，后台只显示“诊断受限/未就绪”，不得抛出 500。请求编号类通用错误应先在 `storage/logs/app.log` 按 `request_id` 定位；诊断代码本身必须 fail-soft。


### 7.2 Go 状态页判定

后台 Go 状态区不再使用表单 flex 布局，SHA 只显示前 12 位并保留完整 title，避免桌面与窄屏错位。状态按部署链明确区分：未部署、current 二进制缺失、部署/二进制不一致、未运行、运行版本不一致、端口未监听、探针受限、正常。若“已部署版本”存在但“正在运行版本/当前二进制”为空，应判定为部署链未完成，而不是要求继续手填 chat.json。


### 7.3 共享 PHP 数据库的 MySQL 合同

自动模式的 `shared_app_credentials=true` 复用现有 PHP 数据库与账号。该模式只校验当前 Go 连接确实选中目标数据库，并保持 UTC、utf8mb4、STRICT_TRANS_TABLES；不再要求整个 PHP 数据库必须是 MySQL 5.7、默认 `utf8mb4_unicode_ci`，也不执行专用 Go 账号的 SHOW GRANTS 白名单。独立低权限模式继续保留原严格合同。依赖探测会返回更具体的安全错误码，例如 `CHAT_DATABASE_SELECTION_INVALID`、`CHAT_DATABASE_SESSION_INVALID`、`CHAT_DATABASE_GRANTS_INVALID`。


### 7.4 current 链接只作为诊断辅助

PHP 后台可能受 open_basedir 或函数限制而无法读取 `chat/bin/current`。Go 就绪判定不再把 current 链接作为硬条件：只要 deployed SHA 与 running SHA 一致且公共端口已监听，即视为 Go 正常；current 读取不到时仅显示“诊断不可见”。若 current 可读但与运行版本不一致，则服务仍可运行，但提示在下次重启前重新部署修正链接。


## 8. 测试站文字消息真实收发（2026-11-01）

基础 Go/MySQL/Redis、身份、会话、历史和 Socket 就绪后，自动运行配置在 test 环境进一步检查：聊天总开关、2.7.x 聊天消息/风控/治理表、小程序 AppID、恢复门禁和 Redis。条件齐全时自动开启 `messages.enabled`，同时使用 `safety.mode=local` 和 `release.staging=true` 完成真实文字发送、持久化、历史读取与 Socket 推送。

test 的 local 安全模式仍使用真实登录身份、订单权限最终复核、账号限制、同会话两分钟短窗口，以及手机号/微信号/链接/拆分规避等本地反私单规则；只跳过微信 `msg_sec_check` 外部请求。production 明确禁止 local 模式，仍需正式发布凭证和正式内容安全门禁后开放。2026-11-01 起测试站在文字链路就绪后会继续按各能力的真实前提自动尝试开启图片、语音/视频、短信和通话；缺少供应商或系统工具时只关闭对应能力。


## 9. 测试站全能力自动开启（2026-11-01）

用户要求图片、语音、视频、短信和通话全部进入真实测试。自动配置按“请求全开、真实前提分项门禁”执行，不再要求手改 chat.json，也不允许空凭据把 Go 整体拖垮：

- 图片：复用现有七牛私有空间、PHP 图片处理器、Python 图片检查器和 2.7.x 图片表；条件齐全自动 `images.enabled=true`。
- 语音/视频消息：复用七牛、小程序 AppID/Secret、微信短期 access_token 导出、Python、FFmpeg/FFprobe、ASR API Name 和 AV 表；全部满足才同时开放 audio/video。文字仍走 test 本地反私单规则，AV 的 ASR/media_check_async 继续使用真实微信凭据。
- 短信：只有现有阿里云短信开关、AccessKey ID/Secret、短信签名、chat_unread_nudge 模板、PHP cURL、测试真实短信开关及接收白名单全部有效时才开放候选桥；报价入口使用相同就绪判断，不会在缺供应商配置时承诺可发送。
- 通话：除 test 消息链路、Redis、通话表、内部签名和 HTTPS 私有 PHP `/chat-calls.php` 端点外，还检查现有供应商凭据及有效资源池。声网 AppID、App Certificate（签 Token）、REST Customer ID/Secret（停止/查询）各司其职，通过既有签名私有接口动态读取，不复制到 Go 配置或前端。只有经过核验、用量新鲜、有可用额度且应用匹配的微信/声网资源池才能开放新通话；已有活动通话时保留停止、查询与对账桥接。
- PHP→Go 内部 HMAC 在 test/development 可从站点 app.key 派生，默认直连 127.0.0.1:19502；production 仍要求显式 CHAT_INTERNAL_KEY 与受保护 HTTPS 内部入口。
- Go→PHP 的通话资源端点不能拿公网普通站点入口冒充。若 Nginx 对公网 `/chat-calls.php` 返回 404，应在后台填写独立 HTTPS 私有 PHP 端点。
- 测试站微信短期凭据由 `chat-credentials.php` 自动导出，Go 启动器每分钟维护；部署和运行均使用 www 身份生成私有文件，避免 root-owned 文件导致 Go 无法读取。
- 媒体本机工具路径和微信服务市场 ASR API Name 在“聊天设置 → Go 服务配置”维护。API Name 必须填写实际已授权商品后台值，不能用 `SentenceRecognitionWX` 猜填。
- 微信媒体安全回调仍需在微信侧完成真实回调地址/加密配置验收；代码启用不等于外部平台已配置成功。真实回调未到达时，AV 消息不得把“等待审核”误报为通过。

全能力状态在后台逐项显示“配置检查通过 / 已请求开启，尚有缺项 / 待独立发布”，明确列出具体缺项，不把配置成功当作供应商已送达。正式站不继承 test 的 staging 自动开放。

### 微信媒体审核回调

1. 在微信后台消息推送使用本站 HTTPS 回调地址：`https://本站域名/chat/api/v1/av/callback`。不要覆盖现有业务消息推送而丢失其事件路由；如已有统一消息入口，先把媒体审核事件按原签名/加密原文转到该处理器，并完成实际回调验收。
2. 在聊天设置填写与微信后台相同的 Token（16至32位字母数字）及 EncodingAESKey（43位）。兼容启动环境已有 `CHAT_WECHAT_CALLBACK_TOKEN` / `CHAT_WECHAT_CALLBACK_AES_KEY`；这些是消息推送密钥，不能用 AppSecret 或 access token 替代。
3. 先保存密钥，不勾选配置确认；后台加密保存，输入框留空保留，不回显密钥。重新编译部署并重启 Go 后，test 会生成 `av.callback_verification=true`，同一地址仅处理有有效签名的 GET URL 验证，POST 审核事件返回503且不确认接收。该验证入口不依赖七牛、ASR或媒体处理工具，不会把音视频消息提前开放。
4. 微信侧 URL 验证通过、地址和密钥一致后，勾选配置确认并保存、重启 Go；所有真实前提都就绪才切换为完整审核回传。更换 AppID、站点 URL 或密钥会使确认失效。正式站不能自动或通过这个 test 专用入口绕过独立发布门禁。
5. 不再用站点 app.key 自动派生一个微信后台并不知道的回调密钥。缺少真实配置、统一 token 过期、回调未确认时语音/视频关闭，文字和图片保持各自独立判断。回调确认属于管理员配置声明，仍需用授权测试账号验证真实审核结果；不得把待审核当作通过。

Go→PHP 内部签名复用既有 `chat.internal_key_env` 指定的有效密钥；test/development 缺少有效密钥时与 PHP 一致从 app.key 派生，避免 PHP 用显式密钥、Go 用派生密钥而互相验签失败。正式站不自动派生。

### 更新范围与部署

本次需要更新 PHP 后台、Go 源码及辅助脚本，重新编译并部署匹配版本的 Go 二进制，不能只更新 PHP 后重启旧二进制。沿用 system_settings 存放工具设置和加密回调配置，不新增集合或 SQL 迁移；前提是站点已完成既有 2.7.x 聊天表升级。正式站保持独立发布门禁，不能仅凭测试站通过就自动开启。配置检测不验证供应商密钥是否被吊销、ASR 商品是否真实授权、外网回调是否可达或消息最终是否送达；这些必须在服务器及授权测试身份下完成真实链路验收。
