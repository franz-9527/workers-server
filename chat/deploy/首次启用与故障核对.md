# 测试站聊天首次启用与故障核对

适用 `/www/wwwroot/workers-test`，PHP 运行目录 `/server`。测试站为 Go `test` / PHP `testing`，公开监听127.0.0.1:19501、内部监听127.0.0.1:19502。正式站保留独立发布门禁。本文按首次使用编写，不安排历史消息迁移。

## 1. 先部署，再在后台操作

本次更新 PHP 后台、Go 源码及启动脚本，需要重新编译部署 Go，不能只更新 PHP 后重启旧二进制。已有 Git 自动部署使用原 `chat/deploy/bt-deploy.sh`；该脚本仅允许测试站，成功后切换编译版本，现有启动器会替换 serve/worker。宝塔项目仍使用原命令：

```bash
/bin/bash /www/wwwroot/workers-test/chat/deploy/bt-run.sh
```

不要另启动第二套聊天进程。运行目录仍为 server，不向公网暴露19502。

进入“聊天管理 → 聊天设置”，按顶部“测试站首次启用”操作：

1. 点击“初始化测试聊天并应用”。仅超级管理员可操作；缺少签名时生成并加密保存，已有签名保留，开启测试站聊天和Redis，不填写或伪造供应商凭据。
2. 配置七牛与聊天分类目录；语音/视频另需媒体工具、微信授权及回调。
3. 保存后点击“应用已保存配置 / 重新检查”；新版启动器约几秒内自动重载。后台只在固定状态目录写入随机应用标记，不执行命令。刷新后可见“等待启动器应用 / 启动器已处理”。
4. “已处理”只表示启动器已读取配置；继续检查版本、端口及各能力状态，再用真实登录的客户/师傅验证。后台模拟身份仍只进入模拟会话。

Redis服务或系统工具未安装时，初始化按钮不会安装软件或假报完成；按缺项说明处理。

## 2. 公开七牛与聊天专用分类目录

本次按当前后台“公开空间 + HTTP 回源”接入，不更改七牛空间ACL，不要求切换私有空间。上传仍使用七牛官方区域 HTTPS 上传域名和精确到对象的短期上传凭证。

在“开发设置 → 存储底层”维护现有七牛密钥、Bucket、域名、区域，并增加“聊天系统分类目录” `qiniu.prefix.chat`，默认 `chat`。测试站沿用 `testing.qiniu_path_prefix` 测试根目录，例如：

```text
test/chat/images/test/账号/随机版本/source
test/chat/images/test/账号/随机版本/文件摘要/main
test/chat/av/test/账号/随机版本/part-1
test/chat/av/test/账号/随机版本/文件摘要/main
```

订单图片、证件和其他分类目录不变。聊天图片使用 images，语音及视频使用 av；分类目录不接受绝对路径、点号或越级路径。默认行在后台设置页按需补齐，不增加SQL迁移。

公开空间的原始地址可直接访问，本站签名链接不会把公开空间变成私有空间；写入、删除等管理操作仍须供应商凭据。[七牛访问控制说明](https://developer-doc.qiniu.com/products/kodo/development-guidelines/management-of-storage-space/1-dev-access-control)。

为兼容现有 HTTP 回源，聊天提供本站 `/chat/api/v1/media/object` HTTPS 入口：仅可读取已签名且属于当前聊天环境的对象，校验有效期、拒绝重复参数和任意远程URL，限制并发与大小，并支持视频 Range 和 HEAD。签名密钥从本站 app.key按环境派生，不暴露给前端。语音识别和媒体审核也使用该HTTPS入口。

小程序后台需配置本站 HTTPS 的 request/downloadFile 域名、本站WSS域名及实际七牛区域的HTTPS uploadFile 域名；不会要求小程序直接访问七牛HTTP回源。[网络说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)。

公开模式目前只在测试站允许，正式站仍需独立发布验收，不随测试站自动打开。

## 3. 媒体检查与 open_basedir

网页只读取 `chat/bin/state/media-preflight.json` 的启动器结果，不检查 /usr/bin、PHP安装目录等系统路径。不关闭或放宽网站open_basedir。

- 尚未检测：显示“等待启动器检查”，不能据此断定工具未安装。
- 配置路径/脚本变化：旧结果标记为待重新检查。
- 已检测失败：才逐项显示 Pillow、zxing-cpp、PHP CLI GD、FFmpeg/FFprobe 等真实失败项。
- 网页与CLI使用一致的配置指纹；不要求FPM能重复枚举CLI二进制。
- PHP必须使用CLI，不能用php-fpm；图片需要GD的JPEG/PNG/WebP支持。
- Python依赖锁定在 `chat/helpers/images/requirements.lock`，对应CPython3.11；建议使用独立虚拟环境，在后台填写其python绝对路径。
- FFmpeg及FFprobe按服务器发行版安装，缺少时只关闭音视频，不影响文字或已就绪的图片。
- 临时目录由CLI创建为0700，运行用户使用现有www。网页无法写启动器状态目录时会明确提示先完成部署。

安装依赖后点击应用重新检查。后台不会将“未检测”展开成一长串“工具未安装”。

## 4. 文字链路

测试站使用真实身份、订单权限和本地反私单风控；不依赖外部ASR或七牛即可收发文字。PHP签名、Redis、聊天总开关、数据表和AppID在后台逐项显示，公共缺项只显示一次。

与现有PHP和Go恢复规则对齐：测试站恢复文件及代次均留空时，使用默认测试恢复状态；若显式配置过门禁，格式和恢复状态仍须满足原有校验，不能用初始化按钮绕过。正式站仍必须具备独立恢复门禁与发布凭证，禁止local风控自动上线。

PHP签名种子加密存于非公开system_settings；Go只获取公钥。自动配置复用PHP数据库和现有Redis配置，不新增聊天数据库。高级兼容模式 `CHAT_CONFIG_MANUAL=1` 保留，常规测试不需要手工chat.json。

## 5. 语音、视频与微信审核回调

小程序AppID/Secret复用后台现有配置，统一access token由PHP维护并导出私有短期文件；Go不持有AppSecret。ASR API Name必须填写实际已授权的微信服务市场商品值，不能猜一个名称。

1. 保存与微信消息推送一致的Token和43位EncodingAESKey，不勾选确认。
2. 应用配置后，测试站同一 `/chat/api/v1/av/callback` 入口先只处理带有效签名的GET所有权验证；POST仍返回503，不假报已处理审核。
3. 微信后台URL验证通过后，再勾选确认并保存、应用；媒体工具、真实短期token、ASR授权配置和回调条件齐全后才启用音视频处理。
4. 若已有统一微信事件入口，保留现有业务事件路由并正确转发媒体审核事件，不能直接覆盖而丢失其他通知。
5. 等待审核、凭据被拒绝或回调未到达不能当作审核通过。

输入框不回显密钥，留空保留；改变AppID、站点地址或密钥后需要重新确认。回调配置确认不等于外网真实回执验收。

## 6. 短信与通话

短信沿用阿里云配置和 `chat_unread_nudge` 模板、原计费与回执流程。需要短信开关、AccessKey、签名、模板、测试真实短信开关、接收白名单及PHP cURL。缺项时对应能力关闭，不替用户开收费短信，不伪造余额或送达状态。

测试站通话默认使用本站HTTPS `/chat-call-bridge.php`，无需另建私有域名。它与原私有 `/chat-calls.php` 共用HMAC验签、时间窗、防重放、恢复门禁及请求限制；新入口只允许PHP testing，正式站返回404。已配置的私有HTTPS端点可继续覆盖默认值。

声网凭据仍由后台“音视频设置”加密保存，通过签名桥接动态提供给Go。App Certificate负责签Token，REST Customer ID/Secret负责供应商控制。资源池必须按真实供应商额度、周期、计量参数、用量和停服核验登记，不能为消除提示编造免费额度；路由和余额必须覆盖双端安全窗口。缺项时不开放新通话，已有通话保留停止和对账能力。

## 7. 验证顺序

先确认Go运行版本与监听，再用真实登录身份创建订单会话、发送文字；随后验证图片、语音、视频、真实审核回传；最后对已授权白名单和真实可用资源池验证短信、通话。模拟会话、配置通过、进程绿色都不替代真实供应商验收。

独立测试仓库负责open_basedir受限网页、公开HTTP回源/HTTPS签名代理、分类目录、配置缺项隔离和实际启动器重载回归；本仓库及本地不执行测试。
