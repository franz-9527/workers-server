# 消息配置请求、发送回执与公告隔离

## 依据与边界

正式站、测试站均出现企业微信卡片已受理但群内未见的反馈。用户提供的 2026-10-29 20:13 和 10-30 14:48 入驻事件均已出队，类型为小程序卡片，机器人指纹一致。因此这两条不能归因为没有触发事件或计划任务没有运行；也不能仅凭 errcode=0 证明群内可见。代码排查和模拟接口测试无法代替目标群实收核对。

群机器人使用企业微信 Webhook JSON 结构。2026-11-01 起按[文本通知模板卡片规范](https://developer.work.weixin.qq.com/document/path/101839)发送 text_notice，跳转指引提供当前站点网页后台与小程序入口；详情见[卡片与路径修复说明](2026-11-01-企业微信文本通知卡片.md)。卡片不支持按手机号 @，后台已明确说明，原配置保留。每个事件只发一次，不在一次请求结果不明时额外降级发送另一条。未知响应、非零错误码和 HTTP 错误均不能记成功。

## 请求修复

过去只拆分订阅测试表单，其他按钮仍使用大配置表单。现在订阅／短信测试、补齐、同步、识别绑定及公共库添加分别拥有原生独立表单和正确的 POST 地址，保留防伪令牌与确认。当前分类保存只提交该分类可持久化字段，由后端与其他已保存分类合并；总开关独立保存。短信模板只传 CODE，不传说明全文；事件开关只传布尔值。

[Nginx 官方说明](https://nginx.org/en/docs/http/ngx_http_core_module.html#client_body_buffer_size)指出请求超过 client_body_buffer_size 时可写临时文件。宝塔提示发生在 WAF 处理阶段，不是微信模板错误。本次减少业务请求，不放开整个后台 WAF、不修改服务器缓冲区。若更新后小请求仍被拦截，应以具体 URL、实际请求体长度和 WAF 记录继续定位，不能直接断言所有拦截都已消失。

## 发送记录

沿用 message_outbox 与 notifications，按渠道、接收对象、状态分类，服务端每页 20 条，翻页保留筛选。展示管理员群通知、客户／师傅订阅、普通和付费短信、聊天订阅以及站内记录。退款请求等财务任务不混在消息列表。聊天历史没有角色字段时明确显示聊天账号，不推断客户或师傅。

业务发送和管理员直接测试保存渠道回执。直接测试失败或请求中断不自动重发；既有业务消息有限重试保持有效。外部接口受理与实际投递分开：显示返回码、受理时间、渠道流水和机器人指纹；企业微信显示送达未确认，因为机器人没有群送达／已读回调。付费短信继续按原投递／计费回执展示。历史缺回执不伪造，缺少记录也不倒填成功。页面不输出 Webhook 密钥、OpenID 或手机号。

## 审核通知与公告

移除管理员投影中写死旧 OpenID 前缀的限制，按通用格式校验云端身份。小程序审核写操作通过 PHP 审核接口及可靠发件箱发送，不再另走云端订阅偏好；保留旧客户端云端回执兼容。审核列表按资料编号查发件箱，等待和未记录状态刷新重查。重新提交清除旧 notice，记录本轮 reviewTime，防止上次审核成功被当作本次结果。文字移除重复的“审核结果通知：”。

首页和门店页原来调用共享云函数中的固定文案，现统一读取当前站点 announcement.current。该接口仅提供公告内容，允许未登录首页读取并禁用缓存。两站内容在各自数据库维护，响应带站点标识；客户端切站清空旧内容、拒绝旧请求和错站响应，页面再次显示时重取。原四个公告场景仍保留。

## 发布影响

- 更新 PHP 后台及 assets/admin.js，浏览器刷新静态资源。
- 更新小程序，才会启用审核接口统一及首页／门店公告隔离。
- 部署 worker 云函数，使用 reviewTime 和重新提交时清除旧回执的逻辑；云函数更新不创建新集合，不改管理员号码查看规则。
- 无 SQL 迁移、无新表、新索引或新云集合。后台公告页仅在现有 system_settings 内补齐首页／门店配置行，默认关闭；两站分别编辑。
- 不自动补发已处理的旧企业微信卡片；部署后使用管理员通知的测试按钮核对目标群，并对照新记录中的文字类型和当前机器人指纹。群内是否恢复需要实际核对，远程模拟测试不会向真实群发送消息。

## 验证方式

仅在独立 workers-server 仓库运行：PHP 语法、真实 MySQL 5.7 分类分页与审核状态刷新、模拟企业微信响应、浏览器实际 POST 大小、公告切站竞态、小程序 WXML 编译及既有师傅资料回归。业务仓库不执行测试，本地不执行测试。

最终验证：[workers-server 远程验收](https://github.com/franz-9527/workers-server/actions/runs/41205909672) 全部通过，包含 21 组订阅测试请求、47 组其余实际按钮提交、49 个 WXML 模板编译，以及 4 组手机／桌面明暗界面检查。真实 MySQL 用例覆盖分类分页、管理员测试记录、三渠道业务回执、审核队列状态刷新和旧审核回执排除。所有外部渠道均使用模拟服务响应，未向真实用户或企业微信群发送测试消息。
