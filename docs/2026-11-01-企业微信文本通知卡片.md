# 企业微信文本通知卡片与处理入口（2026-11-01）

## 修复原因

管理员订单测试使用 `/admin/?route=orders.view`，原校验先允许路由中的点号，又在通用业务编号校验中禁止点号，导致本地抛出“企业微信机器人处理页面路径不合法”，没有调用供应商。本次将 route 与 id/order_no 分开校验，同时阻止外部地址、控制字符、重复参数、数组及未知参数；业务中的 orders.view 和 platform-orders.pricing-review 均可正常通过。

订单测试没有真实订单编号，改为进入后台订单列表；真实业务仍按具体订单进入详情。不会为测试创建订单。

## 通知卡片

使用 [企业微信文本通知模板卡片规范](https://developer.work.weixin.qq.com/document/path/101839) 的 `msgtype=template_card`、`card_type=text_notice`。现有群机器人 Webhook 继续使用，无须创建小程序订阅模板。标题最多 26 字，业务信息最多 6 行（标题 5 字、值 26 字），补充说明最多 112 字；截断保持中文编码完整。

跳转指引包含：
- **网页后台处理**：`type=1`，链接由当前站点 APP_URL 和已校验的后台路径生成；整张卡片点击也进入此入口。
- **小程序查看**：`type=2`，复用后台微信设置的 `wechat.miniapp_appid`。入驻/商家资料进入发布审核，订单/核价进入相应工作台页面。提现、实名/收款资料等没有对应小程序办理页时，入口明确为“小程序工作台”，卡片说明实际办理请用网页。
- AppID 缺失或不合法时，小程序项显示“未配置AppID”且不生成假链接；网页入口仍可用。APP_URL 缺失、非 HTTPS、含账户信息/查询/片段或过长时，发送前明确报错。

测试站沿用企业微信发送门禁，卡片来源明确标记“测试站”，网页入口使用测试站 APP_URL；正式站使用自身地址。跳转不包含登录令牌，也不绕过现有管理员权限验证。小程序跳转只包含 AppID/pagepath，打开版本由微信客户端决定；测试站人员仍需核对小程序内当前站点。

模板卡片没有 text 消息的按手机号 @ 字段。旧手机号配置保留，但后台明确说明当前卡片不使用，不额外补发文字提醒。

## 回执和重试

回执同时保存 `message_type=template_card` 和 `card_type=text_notice`，业务队列与管理员直接测试均可显示“文本通知模板卡片”。旧回执无子类型时仅显示“模板卡片”，不再误称“小程序卡片”。

HTTP 错误、非零 errcode、未知响应都不能显示受理成功；不自动降级另发一条。errcode=0 仍只代表接口受理，企业微信没有提供群内送达/已读回执，记录继续显示“送达未确认”。直接测试失败仍停止自动重试。

## 更新与验证

本次需要更新 PHP 后台文件及视图；不需要更新 Go、小程序包或数据库，无新增集合/表/字段。确认两站 APP_URL 各自正确，微信设置已保存 AppID。部署后使用“消息配置 → 管理员通知 → 发送测试通知”在目标群核对两个入口；本次代码验证不会向真实群发消息。旧失败测试不自动补发。

回归在独立公开测试仓库 workers-server 的 GitHub Actions 执行：使用假 cURL 响应验证真实发送类、多场景入口、点号路由、危险输入、缺配置、测试站门禁、供应商拒绝与中文长度边界；MySQL 验证测试/业务回执持久化和分页展示，配置页面验证独立测试表单。
