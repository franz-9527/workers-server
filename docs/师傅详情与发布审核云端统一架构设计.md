## 2. 最终数据边界

| 数据 | 权威位置 | 说明 |
| --- | --- | --- |
| 师傅公开资料、审核状态、图片、位置 | 云数据库 worker | 师傅资料唯一事实源 |
| 用户当前/历史手机号、会员状态 | 云数据库 user | mobile 当前手机号，lastmobile 历史手机号 |
| 会员卡使用关系 | 云数据库 cards | 继续使用已有卡片绑定 |
| 小程序管理员名单、手机号查看策略 | 云端运行配置 | 由服务器后台设置同步 |
| 会员手机号查看日志/24h额度 | 云数据库日志 + 配额文档 | 管理员不写查看日志或额度；会员日志只留安全关联键 |
| 订单、支付、退款、结算等 | MySQL | 本次不改变 |
| 服务器后台账号与权限 | MySQL | workers.manage、users.manage、settings.manage 等继续使用 |

小程序运行时目标链路：

~~~text
小程序
  ↓
wx.cloud.callFunction(worker)
  ↓
worker 云函数
  ↓
云数据库
~~~

服务器后台继续：

~~~text
服务器后台
  ↓
后台权限校验
  ↓
WORKER_ADMIN_SECRET HMAC
  ↓
worker 云函数
  ↓
云数据库
~~~

~~~text
小程序
  ↓
worker.20m.cc PHP
  ↓
微信 access_token / invokecloudfunction
  ↓
worker 云函数
~~~

## 3. 真实师傅与非真实师傅统一规则

所有有效师傅记录统一使用同一关系：

~~~text
worker._id
   ↓
worker._openid
   ↓
user.openid
   ↓
user.mobile / user.lastmobile
~~~

以下能力禁止再按真实/非真实拆成两套代码：

- 发布审核列表
- 姓名/工种/地区搜索
- 手机号搜索
- 师傅详情
- 管理员查看手机号
- 会员查看手机号
- 审核状态修改
- 服务器后台详情与审核

不得再新增 realWorker / fakeWorker / legacyWorker 形式的平行查询与审核函数。

### 3.1 业务资格和数据路径分离

isRealWorker 等属性可以继续用于“是否具备正式报价资格”，但不能决定走哪一套数据接口。

建议统一计算：

~~~text
can_quote = isRealWorker
            && reviewStatus === approved
            && 其他报价条件满足
~~~

所以非真实/历史标记资料仍然可以被统一搜索、统一查看详情、统一查看关联手机号、统一修改审核状态；是否能够正式报价由接单业务单独决定。

## 4. 手机号规则：保留 mobile || lastmobile

本次明确保留两字段。

### 4.1 字段语义

- user.mobile：当前手机号。
- user.lastmobile：用户换号前的历史手机号。
- 用户换号后允许两个字段同时存在。
- 不把 phone、telephone 等其他旧字段加入新的正式查询契约。

### 4.2 手机号搜索

管理员输入 11 位手机号时，云函数内部匹配：

~~~text
user.mobile === keyword
OR
user.lastmobile === keyword
~~~

命中任意一个：

~~~text
user.openid
  ↓
worker._openid
  ↓
worker 记录
~~~

因此旧手机号和新手机号都可以找到同一用户的师傅资料。

### 4.3 查看手机号

查看师傅当前联系方式时：

1. 优先合法 user.mobile。
2. mobile 缺失或格式无效时，才回退合法 user.lastmobile。
3. 两者都存在且有效时，只返回当前 mobile。
4. 前端不需要知道命中了哪个字段。

统一解析逻辑：

~~~text
valid(user.mobile)     → user.mobile
else valid(lastmobile) → user.lastmobile
else                   → unavailable
~~~

### 4.4 禁止做法

- 不把 lastmobile 批量覆盖到 mobile。
- 不因为存在 mobile 就删除 lastmobile。
- 不把手机号复制进 worker 集合作第二主数据。
- 不向普通师傅详情返回完整手机号。
- 不增加 phone 等猜测型 fallback 字段。

## 6. 后台管理员设置与云端同步

后台 wechat.admin_openids 仍是运营人员唯一编辑入口。

因为小程序运行时不再依赖 PHP，所以后台保存后要同步一份运行配置到云端。

建议云端配置包含：

~~~text
key: worker_runtime_config
adminOpenids: [...]
phoneRevealEnabled: true
phoneRevealAdminEnabled: true
phoneRevealMemberEnabled: true
phoneRevealMember24hLimit: 8
version/hash: ...
updatedAt: ...
~~~

集合名称开发时可结合现有结构确定，但只能有一份当前生效配置。

### 6.1 同步流程

1. 后台校验管理员列表和手机号查看设置。
2. 保存 MySQL system_settings。
3. 使用现有服务器 HMAC 通道调用 worker 云函数“运行配置同步”。
4. 云函数覆盖当前云端运行配置并返回 version/hash。
5. 后台记录同步结果。
6. 成功显示“已保存并同步云端”。
7. 同步失败明确显示“后台已保存，但云端尚未生效”，不得伪装成完全成功。
8. 提供重新同步动作。

云端同步失败时，小程序继续使用上一份有效云配置，不回退 PHP。

### 6.2 管理员列表校验

- 去空。
- trim。
- 去重。
- 至少保留 1 位管理员。
- 限制合理最大数量，例如 20。
- 不接受嵌套对象等无关 JSON 结构。

## 7. worker 云函数统一业务核心

原则：

> 调用入口可以不同，但业务实现只能有一份。

### 7.1 小程序直接入口

建议收敛为：

| 动作 | 用途 | 权限 |
| --- | --- | --- |
| getRecordDetail | 普通师傅详情 | 现有公开规则 |
| miniAdmin.identity | 判断当前小程序管理员 | 当前微信 OPENID |
| miniAdmin.reviewList | 发布审核列表/搜索 | 小程序管理员 |
| miniAdmin.detail | 管理员师傅详情 | 小程序管理员 |
| miniAdmin.phoneReveal | 管理员查看手机号 | 小程序管理员 |
| miniAdmin.review | 审核状态修改 | 小程序管理员 |
| member.status | 当前会员状态 | 当前微信用户 |
| member.phonePolicy | 当前详情手机号权限 | 当前微信用户 |
| member.phoneReveal | 会员查看手机号 | 当前微信用户 |

动作名称开发时可微调，但功能不得重新拆回 PHP。

### 7.2 服务器后台入口

服务器后台保留现有 HMAC 管理入口，例如：

- admin.list
- admin.detail
- admin.update
- admin.review
- admin.delete
- 会员 grant/revoke
- 运行配置同步

服务器后台先执行自身权限：

- 师傅管理：workers.manage
- 用户会员管理：users.manage
- 设置同步：settings.manage

再调用 worker 云函数。

### 7.3 共用内部核心

云函数内部抽取类似：

~~~text
listWorkersCore(...)
getWorkerDetailCore(...)
resolveWorkerPhoneCore(...)
reviewWorkerCore(...)
updateWorkerCore(...)
membershipGrantCore(...)
membershipRevokeCore(...)
~~~

小程序入口：

~~~text
requireMiniAdmin(wxOpenid)
→ core()
~~~

服务器入口：

~~~text
verifyServerHmac()
→ core()
~~~

不得维护“小程序审核规则”和“服务器审核规则”两套实现。

## 8. 发布审核页

### 8.1 数据源

小程序发布审核页不再调用 PHP admin.review.records。

改为直接调用：

~~~text
worker / miniAdmin.reviewList
~~~

### 8.2 排序

按正式资料提交时间排序：createTime 记录首次创建；历史 updatedTime 只有与 startDate 的北京时间日期一致时，才参与资料提交排序。地址修改产生的孤立更新时间不能让旧资料置顶。

- createTime 只记录首次创建；完整资料重提刷新 startDate 和 updatedTime；旧版仅刷新 startDate 时同样视为新的资料提交日期。单独修改居住地址不刷新提交日期。
- publishTime 是审核通过/发布生效时间，不参与资料新旧排序。
- 管理员代改、审核和暂停不得刷新 updatedTime。
- 云函数读取创建时间、有效精确更新、提交日期三条数据流合并去重；同日记录按编号稳定排序，前端不直接查数据库。

### 8.3 搜索

支持已有名称、工种、地区等字段。

11 位手机号严格按：

~~~text
user.mobile === keyword
OR
user.lastmobile === keyword
→ user.openid
→ worker._openid
~~~

全部在云函数完成。

### 8.4 返回字段

审核列表只返回页面需要字段。

不得返回：

- worker._openid
- user.openid
- 完整手机号
- token/secret/卡密

## 9. 师傅详情

### 9.1 普通详情

getRecordDetail(workerId)：

- 云函数按 worker._id 读取；
- 返回脱敏详情；
- 不返回 _openid；
- 不返回完整手机号；
- 不请求 PHP。

### 9.2 管理员详情

miniAdmin.detail(workerId)：

1. 从微信上下文取得 OPENID。
2. 校验云端管理员名单。
3. 读取同一条 worker。
4. 返回管理员所需业务字段。
5. 完整手机号仍由专门 phoneReveal 动作按点击获取。
6. 资料编号和归属 OpenID 默认不展开；管理员手动点击后才显示编号并调用 miniAdmin.detail，初始化只做管理员身份识别。

### 9.3 管理员查看手机号

~~~text
requireMiniAdmin()
  ↓
worker._id
  ↓
worker._openid
  ↓
user.openid
  ↓
mobile 优先
lastmobile 回退
  ↓
返回号码
~~~

公开浏览与发布审核列表不返回 _openid；仅已校验管理员可在详情中手动展开资料编号、按需读取归属 OpenID。

## 10. 统一审核

所有师傅统一：

~~~text
reviewWorkerCore(workerId, decision, reason, operator)
~~~

支持：

- approved
- pending
- rejected
- suspended

真实与非真实资料使用同一状态字段、同一数据库更新函数、同一通知/刷新机制。

如果非真实资料不具备正式报价资格，使用 can_quote 等业务资格限制，不另写第二套审核流程。

如业务仍需要 user.isWorker：

- 对存在对应 user.openid 的资料由统一审核核心维护。
- 找不到对应 user 的异常记录在数据审计阶段修正，不增加运行时特殊分支。

- user.vip
- user.vipEndTime

## 13. 云端手机号查看日志与 24h 额度

worker_phone_reveal_logs 只记录会员查看行为，worker_phone_reveal_quota 按会员保存滚动 24 小时不同师傅配额。管理员查看不写日志、不使用会员额度。两个集合在会员实际使用时按需创建，配置同步仅维护 worker_runtime_config。

必要字段：

- viewerKey（由真实 OPENID 单向摘要得到，不保存明文查看者 OPENID）
- workerId
- role
- result
- reasonCode
- createdAt

禁止保存明文手机号副本和卡密。

会员额度：

- 滚动 24 小时。
- 按不同 workerId 计数。
- 同一会员重复查看同一师傅不重复占额度。
- 上限来自后台同步配置。

管理员：

- 不限量。
- 不写手机号查看日志，不读写会员额度集合。

会员的额度和查看日志按既有流程保存；管理员只保留身份与功能开关校验。

## 14. 安全边界

不再把以下方式作为核心安全：

- 隐藏函数名
- JS 混淆
- 前端保存 secret
- 前端 isAdmin
- 前端传管理员 openid
- 管理员多层一次性 token

真正安全边界：

- 微信云函数真实调用者 OPENID
- 云端管理员名单
- 云端会员状态
- 云端看号开关
- 云端 24h 额度
- worker/user 实际数据关系

即使小程序被反编译，知道 miniAdmin.phoneReveal(workerId)，非管理员 OPENID 也只能被云函数拒绝。

数据库安全规则同时应保证：

- 小程序客户端不能遍历 user.mobile / user.lastmobile。
- 小程序客户端不能直接读取管理员配置。
- 敏感信息只由云函数按权限返回。

## 17. 数据审计

当前尚未正式运营，因此不为错误旧结构增加长期兼容层，优先一次性修正异常数据。

### 17.1 worker

每条继续使用的 worker：

- 必须有 _id。
- 必须有可用 _openid。
- deleteTime 状态明确。
- 审核状态可归一化。

### 17.2 user 关联

每条 worker：

~~~text
worker._openid
→ 至少存在一条 user.openid 相同记录
~~~

- 不删除 lastmobile。
- 搜索同时匹配两个字段。
- 查看优先 mobile。
- mobile 无效时才回退 lastmobile。

### 17.4 会员

检查：

- user.vip
- user.vipEndTime
- cards.used
- cards.usedByOpenid

MySQL user_membership_grants 只作为运营/审计资料核对。

## 19. 必须覆盖的回归测试

### 19.1 管理员

- 后台配置管理员 A/B，同步后两者可进入小程序审核页。
- 后台删除 A 并同步，A 失去管理员云函数权限。
- 伪造 isAdmin=true 不可越权。
- 伪造 event.openid 不可越权。

### 19.2 真实/非真实统一

真实师傅与非真实/历史标记师傅分别验证：

- 列表
- 姓名搜索
- 手机号搜索
- 详情
- 管理员看号
- 审核状态修改

必须调用同一组动作和 core。

### 19.3 mobile / lastmobile

测试用户：

~~~text
mobile     = 新手机号
lastmobile = 旧手机号
~~~

必须：

- 搜新号找到。
- 搜旧号也找到。
- 查看号码返回新号。
- mobile 为空或非法时才回退旧号。

### 19.4 方案 B 会员

- PHP 服务器不可访问时，有效会员仍可查看手机号。
- 非会员不能查看。
- 到期会员不能查看。
- 后台关闭会员看号并同步后立即拒绝。
- 24h 不同师傅数量正确。
- 同一师傅重复查看不重复占额度。
- 管理员不限量。
- 普通会员调用管理员 action 不能越权。

### 19.5 服务器后台

必须确认：

- 师傅列表
- 详情
- 修改
- 审核通过
- 改回待审
- 驳回
- 暂停
- 删除/停用
- 会员开通
- 会员撤销
- 管理员名单同步
- 手机号策略同步

后台和小程序操作同一 worker 后，双方刷新必须看到同一状态。

## 20. 故障策略

### 20.1 云端配置同步失败

- 后台不得显示“全部生效”。
- 云端继续使用上一版有效配置。
- 后台明确显示“待同步”。
- 提供重试。
- 小程序不得回退 PHP 获取权限。

### 20.2 云函数失败

- 返回明确错误。
- 不回退前端直查 user。
- 不回退 PHP 手机号接口。
- 不使用第二套权限更弱路径。

### 20.3 数据关系异常

worker._openid 缺失或找不到对应 user.openid：

- 返回明确数据异常。
- 后台可见并修复。
- 不增加 user._openid、phone 等猜测型兼容。

## 21. 最终开发契约

1. 真实师傅与非真实师傅共用一套列表、详情、搜索、手机号和审核实现。
2. 管理员唯一配置入口为后台 wechat.admin_openids。
3. 删除 user.gly、legacyAdmin 等旧管理员兼容。
4. 小程序管理员权限由云函数真实 OPENID + 云端同步管理员名单判断。
5. 小程序师傅详情与发布审核运行时不依赖 PHP。
6. 服务器后台师傅管理继续保留 HMAC 管理入口，并与小程序共享同一个云端业务核心。
7. 采用方案 B：会员状态、手机号策略、24h额度全部由云端运行时判定。
8. MySQL 会员授权记录降级为运营/审计，不再是小程序看号的运行时必要条件。
9. 手机号正式保留 mobile || lastmobile：搜索同时匹配；查看优先 mobile，必要时回退 lastmobile。
10. 前端不再需要 worker._openid，敏感关联全部留在云函数内部。
11. 不允许“云函数失败 → 前端直查/PHP fallback”的双链。
12. 本次应一次性重构并全量回归，不再继续通过局部 RC 补丁叠加兼容。

## 22. 当前实现与部署边界

当前代码已实现以下能力；不以旧版 CI 推断当前线上验收：

- `worker` 云函数新增 `miniAdmin.*`、`member.*` 和 `server.runtimeConfigSync`；
- 小程序发布审核页的 **worker 来源** 已改为直连云函数；门店审核仍属于独立业务，继续使用现有服务器接口；
- 师傅详情中的管理员身份、审核、管理员编辑、管理员看号、会员看号均已改为云函数权限；
- `mine` 页的小程序管理员身份改为 `miniAdmin.identity`，不再由 PHP `bootstrap.identity.is_admin` 决定；
- 后台保存 `wechat` / `worker` 设置时同步管理员名单及手机号策略；“检查云端连接”也会补做一次同步，便于首次部署；
- `mobile` 已确认是当前/最新手机号，`lastmobile` 是上一次手机号；显示/拨打优先合法 `mobile`，手机号搜索同时匹配两者；
- 真实/非真实师傅共用管理员详情、编辑、审核和手机号解析核心；是否允许正式报价仍由订单报价资格独立判断；
- 小程序直审后，MySQL `worker_profiles` 只作为订单体系轻量投影：`bootstrap` 尽力刷新，真正提交报价前必须从云端刷新成功后才判断审核资格；
- 会员 24 小时额度使用 `worker_phone_reveal_quota` 文档保存滚动窗口，审计写 `worker_phone_reveal_logs`，两者均不保存明文手机号副本；
- 服务器后台师傅审核继续通过 HMAC 调用同一云端审核核心，并继续由 PHP 可靠发件箱发送后台入口产生的审核通知；小程序管理员直审则由云函数发送一次，避免双发。

### 22.1 允许保留的服务器能力

“师傅详情不依赖 PHP”指 **详情资料、审核、管理员身份、会员身份、手机号权限/取号** 不依赖 PHP。

管理员详情页里的“短信推送次数”是短信运营台账统计，数据事实源仍在 MySQL/阿里云短信链，因此保留为**管理员主动点击后才请求的独立运营统计**。该请求失败不得影响师傅详情、审核、手机号查看或会员权限。

### 22.2 部署前置

新架构采用 fail-closed：

1. 先部署最新版 `worker` 云函数；
2. 再部署服务器代码；
3. 在后台保存“小程序绑定”或“师傅”设置，或在师傅管理点击“检查云端连接”，完成运行配置同步；
4. 确认同步成功后再发布小程序。

云端管理员配置尚未同步时，小程序不会使用旧 `gly` 或 PHP fallback 临时放行管理员权限。


## 审核结果通知状态补查

发布审核页仍以 worker 云函数资料作为事实源，通知行明确表示“审核结果通知（发给申请人）”，并非企业微信入驻提醒。

云端记录缺少有效 reviewNotice 时，以当前页缺失状态的师傅编号调用 admin.review.records，使用 cloud_ids（逗号分隔、最多 50 个）精确查询。后台仍执行原管理员鉴权和 no-store；不得以另一份列表的同页页码推测相同师傅，因为 PHP 列表的真实资料过滤、历史资料归并与云端列表范围不同。

补查仅合并通知，保留云端资料、顺序和分页。云端有效通知结果优先；后台发件箱读取 pending/processing、processed、可重试失败、终止失败、closed；仅当 next_attempt_at 存在且次数未耗尽才提示自动重试。没有发送记录时显示“未记录审核结果通知”，查询异常显示“审核结果通知查询失败，请稍后刷新”，待审核显示“审核后通知申请人”，不再笼统显示“通知状态未同步”。

部署须同时更新 PHP 和小程序；本次无数据库结构或云函数代码变更。回归在独立测试仓库使用模拟消息接口和隔离 MySQL，禁止真实通知。

## 发布提示与首次加微信引导

发布表单只显示一条资料状态提示：审核中的资料说明可补充保存；已审核资料从服务端策略读取周期和次数，提交确认只说明重新审核。原云端提示中的“步骤：师傅发布—加微信”不再在表单底部重复显示，其他业务提示保留。

首次成功提交后弹出“资料已提交，请添加审核微信，完成资料核对”，确认“去添加”跳转入驻页并定位原审核二维码；选择“稍后添加”不取消提交。待审核档案保留简短的“去添加”入口，入驻流程第二步标明“加微信审核”。小程序只能引导用户长按识别二维码，不能自动添加微信，也不把打开二维码当作已成为微信好友。再次修改不重复弹出首次引导。提交后替换表单页面，避免返回误提交。

底部发布选择层在页面隐藏、返回和组件销毁时清理菜单与导航状态，隐藏的 Tab 不重复绘制消息角标；返回后按当前实际页面恢复选中项。普通详情资料和提示读取不再使用全屏加载遮罩，避免已离开页面的请求阻挡底部点击。

管理员手机号入口显示早于权限结果时，首次点击等待并复用在途权限请求，然后在同一次操作中取号；连续点击合并为一次取号，失败解除忙碌状态并明确提示，页面卸载后丢弃晚到结果。管理员仍由云函数鉴权，号码仍从 worker._openid 关联 user.openid 的 mobile / lastmobile 解析；不新增管理员看号日志或额度读写，会员规则不变。

本轮仅调整小程序及文档，无 PHP、Go、云函数或数据库结构变更。部署须更新小程序代码，无需更新云函数、执行数据库升级或重新配置审核二维码。
