# 订单聊天文档导航

本目录统一保存聊天专项文档，包括Go聊天/PHP订单分工、首期订单沟通、后续私信、媒体/通话、分阶段开发与宝塔部署。**工程按S单元推进；最新执行状态只看开发清单第19节。当前专用分支为chat，未经用户明确指示不合并到其他分支。** 文档存在、示例配置和验收清单不表示代码/服务已经实现。

订单内沟通以履约及时完成为先：首期不提供用户免打扰或手动隐藏；全部合法真实未读保留角标，在线不代替已读，首次到期不随连续消息延后。具体聚合/复查/渠道边界以[总设计第15章](订单聊天系统设计与开发说明.md)为准，正式业务通知独立执行。

聊天图片按[风控第13章](风控、管理员审计与语音识别.md)走本机二维码、可选轻量OCR及人工预审/抽检，不调用微信认证OCR、不默认接云OCR或收费视觉服务；可选OCR的漏识别可容忍，一般内容安全结论单独完成。S16须同时交付最小人工预审入口。

底部“消息”使用独立聊天消息页，重要事项沿用原“我的”卡片样式按需显示，普通通知作为会话行按新消息时间自动混排，点击进入原“通知与待办”的普通通知分页。原处理页面和我的菜单保留，门店由首页“附近门店”进入。页面、C+B+S总角标和偏好边界以[总设计第31章](订单聊天系统设计与开发说明.md#31-独立聊天消息tab与原通知与待办保留设计2026-10-23按用户最终确认修订)为准；实际交付及尚未执行的真机/发布验收只见开发清单第19节。

语音/视频规则见[总设计32](订单聊天系统设计与开发说明.md#32-语音视频消息与分类型留存2026-10-24按用户补充定版)和[协议39](消息协议、已读回执与云端存储.md#39-ext0102分类型留存缓存与续传契约2026-10-24)。2026-10-25最新补充：相机30秒/8MiB、相册120秒/20MiB；图文语音云端默认永久，视频原片默认60天，**只清七牛原片，不清本机已缓存副本；视频封面和抽帧长期保留**。后台云保存期可调、低频默认关闭。设备缓存无额外容量/条数/年龄上限，由用户分类清理；微信键值10MiB与文件缓存分开。代码与测试进度只记清单19节，各入口/生产门禁保持默认关闭。

通话2026-10-26定版：[微信原生+声网共享免费额度](通话月额度、充值与计费.md)。两家分别建平台资源池，语音/视频共用本池，后台展示官方统计水位、平台估算、预占和安全可用量；一池不足选另一可用通道，两池耗尽停用，不设个人分钟/次数/固定单通时长、不充值或转付费。接线与放行边界见[实施联调说明](双通道通话实施与联调.md)，真实额度/用量来源/免费到额强停须先核验，不能把历史数字或页面示例当已开通能力。

余额短信催促是用户主动确认的独立能力，规则见[余额短信催促提醒](余额短信催促提醒.md)；不改变免费订阅提醒不自动转付费短信的边界。

统一聊天审核入口、聊天气泡展示、图片／音视频待审合并及权限说明见[2026-10-30 聊天审核整合](../2026-10-30-聊天审核整合.md)。

后台通话凭据、登记预设与紧凑表单的配置和更新方式见[2026-10-30 后台聊天管理设置优化](../2026-10-30-后台聊天管理设置优化.md)。

## 开发从哪里开始

1. 每轮先看[开发拆分与验收清单第1节](开发拆分与验收清单.md#1-分阶段开发计划与每轮边界2026-10-21执行唯一入口)和[第19节当前交接](开发拆分与验收清单.md#19-当前进度与下一轮交接唯一进度入口)，核验仓库实际分支与代码。
2. 只读本轮相关设计章节/代码和用例，不反复加载整套文档。默认每轮完成一个S单元，目标约15～25分钟；过大拆子单元，必要验证完成后只提交chat，等待用户明确指示后才合并。
3. 工程顺序从 **S01 Go工程与进程骨架** 开始，其后按S02～S23推进；每轮从第19节最早未完成单元接续，不重复S01；后续轮次以第19节为准，未通过的单元先收口，不跳过权限、审核或一致性门禁。
4. 详细进度只更新开发清单第19节；本导航与总设计不重复记录逐轮状态。Git承担历史过程，文档区分代码完成、测试通过、待真机和已部署。

## 目录与维护约定

- 原`docs/订单聊天系统设计与开发说明.md`已移到本目录同名文件；仓库内引用同步改为新路径，根docs不留聊天专项正文或跳转副本。公共样式、消息配置、数据库升级、CI和仓库维护仍在各自公共文档，不因聊天引用而搬进本目录。
