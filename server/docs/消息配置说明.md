# 壁选后台消息配置说明

运营操作入口；发送机制的唯一开发契约在仓库 docs/消息配置开发说明.md。当前配置由已部署代码和 AppID 决定，不依文档旧热修版本判断是否要升级。

## 1. 渠道与保存

当前代码有内部通知 / 微信订阅消息 / 短信通知 / 管理员通知四个分页，保存后停留当前分页。
内部通知控制消息中心事件，仍有效的历史未保存项默认开启；它不自动改变外部通知。微信订阅按左侧场景切换、右侧编辑，每个通知单独保存，总开关单独保存。

## 2. 配置微信模板

按身份配置重要通知：客户订单、客户财务、师傅订单、师傅财务，以及双方通用的聊天未读。各身份一次重要续收最多申请“本身份订单＋本身份财务＋聊天”三个模板；系统模板总数不限制为三个。上门预约、收到评价等普通通知可另行配置、单项授权，入驻审核继续在入驻流程单独开启。

订单与财务模板的“提示/说明”映射当前事件，如费用调整待确认、维修进度提醒；订单编号和时间也需配置，额外实际字段逐项补全。不要为每个进度重复申请模板。原有共用订单模板仍兼容，同一 ID 共用一份授权次数；单独配置财务 ID 后才分开授权和计数。编辑单项不会清空其他已保存分类。


1. 选择业务通知，粘贴已有 priTmplId 并识别，或打开公共模板库。
2. 公共模板库先选具体类目、输入模板关键词，再点击搜索；打开/切类目不自动搜索。
3. 单次最多检查 90 条标题；需要更多时手动“继续搜索”。45009 时停止，不连续重试耗尽额度。
4. 选择模板与 2～5 个关键词后添加并绑定，程序同步真实标题、字段与订阅类型。
5. 自动映射无法判断时再打开高级设置，选业务来源或填固定文字；字段名填 time3，不填 {{time3.DATA}}。
6. 每个微信字段都要有来源，缺项保存为待配置且不会发送。入驻审核 reviewResult 使用专用固定字段，不手动补通用映射。
7. 保存当前通知，再测试；识别/绑定/保存/测试后留在原通知。其他场景未保存内容不会被一起写入。

## 3. 授权与测试

一次性通知每次合法授权 +1，微信成功发送后 -1；总是保持选择不等于长期订阅。每次最多 3 类且不混一次性/长期。
小程序设置保持分组卡片、次数和单项开启；微信次数不足与业务待办、聊天新消息共用程序内顶部悬浮通知，点击才会请求授权，不与入驻审核状态混排。权限关闭或明确拒绝则进入通知设置。普通用户自诊断只读状态，不清缓存或本地草稿。
后台真实测试仅选择已配置、已登录并已授权的管理员号，使用已保存配置；成功会消耗一次性次数。真实短信测试产生短信费用。管理员通知页可选择订单审核、师傅/商家审核或提现场景，使用已保存的企业微信机器人配置发送明确标注的测试通知；无需开启对应业务事件，但必须先保存并启用机器人，测试环境仍遵循外发开关。成功表示企业微信受理，需在群内核对内容及小程序/网页处理入口。

## 4. 短信与企微

- 建议短信可独立发送；订阅失败兜底仅在微信不可用/最终失败且对应设置允许时发送；其他可选短信按需开启。
- 应用精简方案只开推荐，高可靠方案再开重要兜底；都需主动应用，不自动改运营开关。
- 预约费支付成功、退款到账等重复通知已退出站内/订阅/短信渠道，旧开关无法重新开启；退款审核、待付款和退款处理中仍保留。测量付款仅通知需要继续履约的师傅，不再重复提醒付款人。
- 预计服务费、系统自动评价和测量单关联施工单不再生成独立通知；业务事实继续在订单记录中保留。
- “聊天消息通知”是重要订阅，用户和师傅均可续收。持续未读时聚合提醒、已读后停止，通知不含聊天原文，也不自动转成收费短信。
- nearby_worker_invite 使用独立已审核模板 CODE，只包含 category/district/distance，不含链接/号码/详细地址；用户主动付费邀请与普通事件开关分开。
- 管理员通知固定标明“接收：管理员”，另以“触发来源”说明用户、师傅、管理员或系统操作；历史无法判断来源时明确显示未记录。
- 企微只面向管理员待办/异常。存在等价小程序处理页时使用企业微信 Webhook `template_card` 原生小程序跳转（`appid + pagepath`），不再先生成微信 URL Link；师傅入驻进入“发布审核”，订单事项进入管理员订单工作台。只有没有对应小程序处理能力或原生卡片发送失败时才降级受控 HTTPS 网页后台。

## 5. 消息发送记录与抑制名单

后台“消息发送记录”分为两个分页：

- **发送记录**：展示渠道、业务说明、技术业务编号、状态、重试次数和脱敏后的最近错误。界面优先把 `event_type`、`scene_key`、消息标题等转换为“师傅入驻审核”“商家认证审核”“订单取消 / 退款申请”“附近师傅短信邀请”等业务含义；`business_key` 只作为排障编号保留。页面不展示手机号、OpenID 或完整消息正文。
- **附近师傅短信抑制名单**：独立分页管理明确退订、投诉或人工风控号码；保存脱敏手机号与 HMAC，不保存明文号码。加入、解除后均停留在该分页。

发送记录和抑制名单都使用后台通用分页。普通外部消息达到死信条件后才允许人工重试或结案；付费附近师傅短信仍以独立投递、计费状态为准，不通过普通消息重发入口处理。

## 6. 运行日志与排障

后台“系统 → 运行日志”统一查看 `storage/logs/*.log`，包含 APP 全局异常、API / 支付回调、后台管理、消息通知、计划任务和升级维护等通道。页面只读取每个文件末尾最多 256 KB，并对手机号、Bearer/token、OpenID/secret 和企业微信 Webhook key 等常见敏感字段做展示脱敏。

日志容量长期规则：

- 单个活跃日志达到 **8 MB** 后自动滚动为带时间戳的归档文件；
- 每个日志通道最多保留 **5** 份归档；
- 超过 **30 天** 的归档自动删除；
- 管理员可手动清理 7 / 15 / 30 / 60 / 90 / 180 天以前的日志，或清空某个明确日志文件；
- 自动维护最多每小时执行一次，并在请求结束后执行，不能因为日志维护阻塞正常业务。

后台日志管理只能访问 `storage/logs` 下受限命名的 `.log` 文件，不接受任意服务器路径，也不处理上传文件、安装锁、配置或数据库。

## 7. 排查与验收

先核对当前 AppID、模板完整度、次数、计划任务运行和本人发送记录。普通外部消息有 processing 租约与有限重试，5 次失败后按供应商结果决定人工重试或结案。
收费短信受理不等于送达，delivered + charged 才是收费成功；不能通过普通失败消息按钮重发。
出现后台/API 500 时优先用页面给出的 request_id 到“运行日志”搜索；确认是业务异常、第三方回调还是配置问题后再处理，不需要直接进入服务器翻完整日志文件。
验证真实授权/回调/送达与演示隔离，历史 CI 成功不代表当前外部服务已联调。

本次分类与悬浮通知需要同步更新 PHP 后台及小程序，无新增数据库迁移；旧版本升级仍需完成既有迁移。完整规则见 [按身份订阅与统一悬浮通知](../../docs/2026-10-31-角色订阅与统一悬浮通知.md)。

## 微信订阅测试被宝塔 WAF 提示缓冲区溢出

更新后的“发送测试”使用独立的小表单，只提交防伪令牌、当前通知分类、测试管理员和测试事项，不再附带全部模板 JSON、其他分类参数或未保存的配置。测试始终使用后台已保存的模板；修改后请先保存当前分类，再测试。此次仅需更新 PHP 页面和后台 admin.js，无数据库迁移或小程序更新。

如果发送时看到宝塔的缓冲区提示，请先确认已部署本次页面和脚本、刷新浏览器后重试。该提示发生在站点防火墙处理请求时，不代表微信已拒绝通知；仍需以后台实际返回的发送结果为准。若独立小请求仍被拦截，再结合该请求的大小、WAF 记录和 Nginx 配置定位。
